## 修复方案:让"开机自启动"真正可用

### 背景
设置里已有开关(SettingsView.swift:85),用 `SMAppService.mainApp.register()`。但用户机器上 BTM 无条目、无偏好记录 —— 注册从未成功。三处缺陷:无降级路径、UI 状态不与系统真实状态同步、登录项静默失效后无法自修复。

### 改动

**1. `Sources/LaunchAtLoginService.swift` — 核心重写**
- 协议增加 `var isEnabled: Bool { get }`(查询系统真实注册状态)
- `SMAppLaunchAtLoginService`:
  - `setEnabled(true)`:优先 `SMAppService.mainApp.register()`;抛错时**自动降级**到 `LSSharedFileList` 传统登录项(对所有签名/系统版本都有效,作为兼容层)
  - `setEnabled(false)`:同时清理 SMAppService 注册与 LSSharedFileList 条目
  - `isEnabled`:SMAppService status == .enabled **或** LSSharedFileList 中能找到本 app URL
- 新增 `import CoreServices`(LSSharedFileList 已废弃但 macOS 13+ 仍可用)

**2. `Sources/SettingsViewModel.swift` — 状态同步**
- `loadLaunchAtLoginPreferenceIfNeeded()`:开关初始值以**系统真实注册状态**为准(真实状态 > 偏好文件),不再仅读偏好

**3. `Sources/main.swift` — 启动自修复**
- `applicationDidFinishLaunching` 中:若偏好为 true 但 `isEnabled == false`,自动尝试重新注册(修复"重装/签名变化导致登录项失效、重启不自启动"的场景)

**4. 测试**
- `Tests/Mocks/TestMocks.swift`:Mock 增加 `isEnabled` 支持
- `Tests/SettingsViewModelTests.swift`:新增"加载时以真实状态为准"用例
- 新增 `Tests/LaunchAtLoginServiceTests.swift`:用 mock 子服务测试降级组合逻辑(SM 失败→LSSharedFileList、清理时两者都清)——不触碰真实系统登录项

**5. 本地验证**
- `xcodebuild test` 全绿(352+ 用例)
- 在用户机器上真实打开开关,确认 BTM 出现 `com.nicebro.ClipShelf` 条目

### 不做的事
- 不改语言文件(复用现有 `settings.launchAtLoginFailed` key)
- 不挪动/重排设置 UI(开关保持在 General 页原位置)
- 不改变发布流程(Developer ID 签名版走 SMAppService 主路径,行为不变)
